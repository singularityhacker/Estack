Complete `Inbox.Webhook.receive/3` in `lib/webhook.ex`. `raw_body` is the untouched request binary. The verifier callback accepts those bytes and returns `{:ok, event}` or `{:error, :invalid_signature}`. The persistence callback stores the verified event and work atomically; it returns `:ok`, `{:error, :duplicate}`, or another `{:error, reason}`.

Return `{:ok, 202}` after durable acceptance, `{:ok, 200}` for a previously accepted duplicate, `{:error, 401}` for an invalid signature, and `{:error, 503}` when persistence fails so the provider can retry. Unexpected callback exceptions should propagate to the normal error boundary. Do not acknowledge before persistence, mutate the signed bytes, or call persistence after a failed signature. Keep the existing callback interface; adapters handle HTTP and the database separately.
